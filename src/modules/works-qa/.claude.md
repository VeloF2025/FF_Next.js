# works-qa module

Works QA Dashboard for pole photo sweep workflow (civil, dome, main joint disciplines).

**Page:** `/field-ops/works-qa`
**API routes:** `pages/api/works-qa/` — 12 flat routes: `poles`, `pole-detail`, `pole-assign`, `pole-approve`, `pole-comment`, `pole-override`, `sync-qfield`, `sync-historical`, `pon-zip`, `zones`, `recent`, `recent-seen`
**DB table:** `pole_qa_photos` — 8 civil (`civil_step_0{1-8}_key`, step 08 added mig 388) + 8 dome (`optical_dome_0{1-8}_key`) + 6 main joint (`main_joint_{11-16}_key`) TEXT columns + `main_joint_tray_keys TEXT[]` + `vlm_results JSONB` + `civil_approved / dome_approved / joint_approved` booleans
**Slot shape:** `SLOT_META` in `slot-keys.ts` defines 21 slots keyed `civil_01`…`dome_08`…`main_joint_11-16`; `dbColumn` maps each to the DB column; `ALLOWED_PHOTO_COLUMNS` Set guards all dynamic column interpolation
**VLM:** `worksQaVlmService.ts` → `VLM_CHAT_ENDPOINT` (constants from `@/lib/vlm`, uses `stripThinkTags`); returns `{valid, confidence, feedback}`; HTTP failure returns safe fallback (never throws)
**Approvals:** per-discipline — `pole-approve` calls `disciplineGatesPass(pole, discipline)` NOT `allGatesPass`; gates require every slot in that discipline to have a photo + VLM pass-or-override; `main_joint` also needs `main_joint_tray_keys.length >= 1`; DB column for main_joint is `joint_approved` (legacy name); `approved_at` set only when all three booleans are TRUE
**VLM override learning:** `pole-override` writes to `qa_correction_examples` with `workflow_type='works_qa'`; encodes discipline as category string
**Dual-step photo reuse:** `link-photo` (POST) copies one photo into a SECOND slot in ANY discipline (e.g. a depth shot that also shows end-plates, or a wide pole shot evidencing both the dome and the main joint) — source slot keeps its photo. Sets target `vlm_results[slot]` to `{valid:true, overridden_by, dual_step:true, source_slot}`. **Deliberately does NOT write `qa_correction_examples`** (unlike `move-photo`/`pole-override`) — it's "one photo, two steps", not a VLM misclassification, so logging it would poison training (this matters even more cross-discipline). UI: `getLinkCandidates()` (all-discipline, has-photo; each candidate tagged with `disciplineLabel`) → `SlotPhotoPicker` modal, triggered by "⧉ Use existing photo" on `PhotoSlotCard`. Cross-discipline reuse enabled 2026-06-11 (originally same-discipline only, PR #1911).
**QField sync:** `sync-qfield` reads `qfield_photo_validations` joined via `qfield_project_links` (QField IDs ≠ FibreFlow IDs); maps `checklist_step` + `work_type` to slot key; never writes back to QField; skips slots already populated
**Historical backfill:** `sync-historical` reads `construction_qa_photos` / `construction_qa_reviews`; fills nulls only (no clobber); copies approval flags from `workflow_status='approved'` rows
**Comments:** `pole-comment` — append-only per discipline, max 2000 chars
**SQL safety:** `ALLOWED_PHOTO_COLUMNS` Set (derived from `SLOT_META`) guards every dynamic `colName` interpolation in both `sync-qfield` and `sync-historical`
**Planned→planted→QA'd funnel:** PON overview shows a 3-stage funnel. `planned`=`sow_poles` (zones rollup); `QA'd`=`pole_qa_photos`; the middle `planted` stage = `poles.field_status` (the QField civil-audit `Status`, mig 424). `poles.ts` unions photographed (`pole_qa_photos`) ∪ planted-only (`field_status` set, NOT in `NOT_PLANTED_STATUSES`, `NOT EXISTS` photo) so the sets are disjoint. **`field_status` is a raw mirror of the GPKG `Status`; the planted/removed classification lives ONLY in `poles.ts` `NOT_PLANTED_STATUSES` (deny-list: two removal spellings `Pole Removed/Canceled` + `Pole Canceled / Removed`, plus `To be Planted`; unknown→planted).** Ingest: `scripts/sync-qfield-status-to-ff.py` (nightly cron `scripts/cron/sync-qfield-status.sh`, ~00:45 SAST) reads each project's poles GPKG from MinIO and upserts `field_status` — per-project `table`/`label`/`status` config in the script's `PROJECTS` dict (verified, not assumed — POP 1 uses `label_1`, POP 3 uses `label`; QField drops the `_1` on republish, which froze POP 3 for 3 days, so `require_column` now fails loudly on a stale name).
**Recent submissions feed:** `recent` (GET) powers the overview's "Recent submissions" panel — keyed on `(pole × discipline)` since civil/dome/main_joint complete weeks apart. Per-discipline recency = `MAX(qfield_photo_validations.validated_at)` joined via the photo_key stored in each slot column (no dome-label parsing — sync already resolved it). Buckets: **ready** (all discipline slots present + unapproved) and **partial** (some slots). Windows: `since_last` (default) / `3d` / `7d`. Rollup logic is in `utils/recent-rollup.ts` (unit-tested); SQL column interpolation guarded by `SAFE_COL` regex over `SLOT_META`. **Watermark:** `recent-seen` (POST) + `works_qa_view_watermark` table (mig 403, keyed by email) back "since I last opened" — `recent` GET auto-advances `cutoff_at` with a 30-min session debounce (refresh-safe); "Mark caught up" forces it to now.
**HT hierarchy:** In HT civil-audit projects, `Phase N` is Works QA Zone `N`. PON must come from an explicit audit PON column or a verified design-layer spatial join; never infer it from a pole ID or label.
