## Taxonomy (Two-Axis)
- **TicketType** (which discipline resolves): `civils`, `optical`, `activations`, `maintenance`, `dev_ops`, `unspecified`
- **TicketCategory** (kind of issue): `maintenance`, `snag`, `hse_incident`, `dev_ops`, `sales_lead`, `unspecified`

## Status Flow
`open` → `assigned` → `in_progress` → `pending_qa` → `qa_in_progress` → `qa_rejected|qa_approved` → `pending_handover` → `handed_to_ops` → `resolved` → `verified` → `closed`

## Critical Rules
- NEVER hard-delete tickets — `CANCELLED` is the terminal soft-delete state
- Ticket UIDs (`VF-YYYYMMDD-NNN`) use atomic DB sequence — never generate manually
- QContact Note creation returns 403 for Velocity account — fallback appends to `description` field (expected behaviour)
- Custom QC fields (`c__update`, `c__feedback`) are dropdowns — reject free text
- `assigned_team` and `assigned_team_id` must stay in sync — write both on assignment
- API routes split: `/api/noc/` (new) and `/api/maintenance/` (legacy) — both active
- Check for duplicate open ticket on same DR/ONT before auto-creating (`duplicateTicketService.ts`)

## Common Issues
| Issue | Fix |
|-------|-----|
| QContact note 403 | Expected — falls back to `description` PATCH; no action needed |
| Duplicate auto-tickets | Run `duplicateTicketService.checkExisting()` before creation |
| Team not auto-assigned | Verify `teams.discipline` matches `TicketType` enum value |
| QContact sync stuck | Check `maintenance_qcontact_sync_log`; 30s cooldown on auth retry |
| Storage upload fails | Use `vfStorageAdapter` — never Firebase, never direct file paths |
