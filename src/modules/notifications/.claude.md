# Notifications Module (Unified Notification Service — UNS)

## Purpose
Central notification bus for all FibreFlow modules. A single `notify()` call dispatches
to three delivery channels: in-app bell icon (always stored), email via Resend, and
WhatsApp (group message via bridge on :8092, or individual DM via WAHA on :3001).
User preferences (per event type, per channel) override system defaults.

## Key Files
| File | Purpose |
|------|---------|
| `services/notificationBus.ts` | Core `notify()`, `getEffectiveChannels()`, read helpers |
| `services/emailDelivery.ts` | Resend email dispatch + default HTML template |
| `services/whatsappDelivery.ts` | WA group (bridge :8092) + individual DM (WAHA :3001) |
| `services/index.ts` | Barrel export — all callers import from here |
| `constants/index.ts` | Event registry: default channels, icons, severity, labels, groups |
| `types/index.ts` | All TS types: `NotifyPayload`, `UserNotification`, `ChannelPreferences`, etc. |
| `hooks/useNotifications.ts` | TanStack Query hooks: `useUnreadCount` (30s poll), list, mutations |
| `hooks/index.ts` | Barrel export for hooks |

## API Endpoints
| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/notifications` | List notifications — query params: `limit` (max 100, default 20), `offset`, `unread_only` |
| GET | `/api/notifications/unread-count` | Returns integer count for bell badge, polled every 30s |
| POST | `/api/notifications/mark-read` | Body: `{ notification_ids: string[] }` — returns `{ updated: number }` |
| POST | `/api/notifications/mark-all-read` | Marks all as read for authenticated user |
| GET | `/api/notifications/preferences` | Returns `MergedPreference[]` (system defaults + user overrides) |
| PUT | `/api/notifications/preferences` | Body: `{ preferences: { event_type, channel_in_app, channel_email, channel_whatsapp }[] }` |
| POST | `/api/notifications/test` | Dev-only (or admin in prod): sends test notification to self |

All endpoints use `withAuth` middleware — `authReq.user.id` is the scoping key.

## Types
```typescript
// Primary payload — callers construct this
interface NotifyPayload {
  event_type: string;             // e.g. 'maintenance.ticket_assigned'
  title: string;                  // shown in bell dropdown
  body?: string;                  // optional detail text
  icon?: string;                  // Lucide icon name (defaults from EVENT_ICONS)
  severity?: NotificationSeverity;// 'info'|'warning'|'error'|'success'
  action_url?: string;            // in-app link on click
  source_module?: string;         // e.g. 'maintenance'
  source_id?: string;             // UUID of source entity
  metadata?: Record<string, unknown>;
  recipient_user_ids: string[];   // callers resolve recipients before calling
  email_html?: string;            // custom email HTML (else default template)
  email_subject?: string;         // custom subject (else title)
  wa_group_jid?: string;          // send to group instead of individual DM
  wa_message?: string;            // custom WA text (else title + body + url)
}

type NotificationSeverity = 'info' | 'warning' | 'error' | 'success';
type NotificationChannel = 'in_app' | 'email' | 'whatsapp';

interface UserNotification {      // row from user_notifications table
  id: string; user_id: string; event_type: string;
  title: string; body: string | null; icon: string;
  severity: NotificationSeverity; action_url: string | null;
  source_module: string | null; source_id: string | null;
  metadata: Record<string, unknown>;
  is_read: boolean; read_at: string | null;
  created_at: string; updated_at: string;
}

interface MergedPreference {      // returned by GET /preferences
  event_type: string; label: string; group: string;
  channel_in_app: boolean; channel_email: boolean; channel_whatsapp: boolean;
  is_user_override: boolean;
}
```

## Architecture

```
Caller module
    │
    └─► notify(payload)                  notificationBus.ts
             │
             ├─ getEffectiveChannels()   DB: notification_preferences (user override)
             │                           Fallback: DEFAULT_CHANNEL_PREFERENCES[event_type]
             │                           Fallback: _fallback = { in_app:true, email:false, wa:false }
             │
             ├─ [in_app] INSERT user_notifications
             │
             ├─ [email]  deliverEmail()  → Resend API (FROM: notifications@fibreflow.app)
             │           └─ lookup user email from users table
             │           └─ build HTML or use payload.email_html
             │           └─ INSERT notification_delivery_log (sent|failed)
             │
             └─ [wa]     deliverWhatsApp()
                         ├─ group: POST :8092/send-message { group_jid, message, recipient_jid? }
                         └─ DM: lookup phone from staff.phone → users.phone
                                POST :3001/api/sendText { session, chatId, text }
                                chatId = 27xxxxxxxx@c.us
```

**Channel resolution precedence:**
1. User row in `notification_preferences` (exact `user_id + event_type` match)
2. `DEFAULT_CHANNEL_PREFERENCES[event_type]` from constants
3. `_fallback` = `{ in_app: true, email: false, whatsapp: false }`

**Delivery is fire-and-forget:** email and WA errors are caught and logged; they never
throw back to the calling module or the bus loop.

## Database Tables
| Table | Purpose |
|-------|---------|
| `user_notifications` | In-app notification store; indexed on `(user_id, is_read, created_at DESC)` |
| `notification_preferences` | Per-user per-event overrides; UNIQUE on `(user_id, event_type)` |
| `notification_delivery_log` | Audit trail for email/WA — status: `sent|delivered|failed|skipped` |

Migration: `scripts/migrations/192_unified_notifications.sql`

## Critical Rules
- **Never let notify() throw to callers** — always call as `notify({...}).catch(() => {})` from external modules
- **Callers resolve recipient_user_ids** — the bus does not look up who to notify; the calling module must pass resolved UUIDs
- **No conditional SQL fragments** — use explicit `null` values, not ternary `sql\`AND x\`` expressions (breaks Neon tagged templates)
- **Flat API routes only** — no nested dynamic routes; Vercel will fail on those
- **Adding a new event type** requires updates to ALL FOUR constant maps in `constants/index.ts`: `DEFAULT_CHANNEL_PREFERENCES`, `EVENT_ICONS`, `EVENT_SEVERITY`, `EVENT_LABELS` (and `EVENT_GROUPS` for UI grouping)
- **Phone formatting for WAHA DMs:** `0821234567` or `+27821234567` → `27821234567@c.us`
- **Email is lazy-imported** (`import('@/lib/email/resendClient')`) to avoid build-time errors if `RESEND_API_KEY` is missing

## Dependencies
- **External:** `@neondatabase/serverless`, `resend` (via `@/lib/email/resendClient`), WA Feedback proxy (:8092), WAHA (:3001)
- **Internal:** `@/lib/logger`, `@/lib/apiResponse`, `@/lib/auth/middleware`, `@tanstack/react-query` (hooks only)

## Common Patterns
```typescript
// Sending a notification from any module
import { notify } from '@/modules/notifications/services';

notify({
  event_type: 'procurement.approval_needed',
  title: 'PO approval required',
  body: `PO #${po.number} needs your approval`,
  action_url: `/app/procurement/approvals/${approvalId}`,
  source_module: 'procurement',
  source_id: po.id,
  recipient_user_ids: [approverUserId],
}).catch(() => {}); // fire-and-forget; never await in a request handler

// Adding a new event type — update constants/index.ts:
DEFAULT_CHANNEL_PREFERENCES['mymodule.new_event'] = { in_app: true, email: true, whatsapp: false };
EVENT_ICONS['mymodule.new_event'] = 'bell';
EVENT_SEVERITY['mymodule.new_event'] = 'info';
EVENT_LABELS['mymodule.new_event'] = 'Human Readable Label';
EVENT_GROUPS['mymodule.new_event'] = 'My Module';
```
