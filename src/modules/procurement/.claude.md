## GRN Confirm Workflow (2026-01-25)
When confirming a GRN via `/api/procurement/grn-confirm`:
1. Validates GRN is in `draft` or `receiving` status
2. Creates `stock_movement` with `source_type='fibreflow'`
3. Creates `stock_movement_items` for each GRN line
4. Updates `stock_items.qty_available` (accepted = received - rejected)
5. Updates GRN status to `completed`

**Note:** Trigger `tr_grn_stock_update` is DISABLED - the API handles stock updates directly.

## BOQ Import Pipeline (2026-02-12)

**Import flow:** Excel upload → column detection → column mapping review → import with material/stock matching

### Stock Matching Pipeline (4 stages)
1. **Supplier code lookup** — exact match via `supplier_item_codes` table
2. **Exact/prefix item code** — direct code match or BOQ code starts with stock code
3. **Fiber domain match** — category→prefix mapping + parameter scoring (connectors, length, diameter, fiber count, model, size range, variant)
4. **Fuzzy description** — keyword overlap + Levenshtein (threshold 0.55)

### Stock Item Code Conventions (actual stock)
| Category | Prefix | Example |
|----------|--------|---------|
| Drop cables | `DROP-APC-{len}-{dia}` | `DROP-APC-10-3` |
| Aerial cables | `CAB-AER-SM-{dia}-{fiber}F` | `CAB-AER-SM-9.6-24F` |
| Tangents | `TANGENT-{range}` | `TANGENT-10.80-11.49` |
| Dead-ends | `DEADEND-{range}` | `DEADEND-9.2-9.5` |
| Enclosures (SJC) | `SJC-{model}` | `SJC-ODCFD0` |
| Splice joints | `DOME-{model}` | `DOME-CMJ` |

### Performance: Pre-load materials for batch import
**Problem:** Per-row DB queries (3+ per item × 250 = 750+ queries) cause Cloudflare timeout.
**Solution:** Pre-load all materials once with `getAllMaterials()`, match in-memory with `matchItemWithCache()`.

## Learnings (Consolidated 2026-01-21)

### Neon PostgreSQL Type Handling
- Neon sometimes returns numeric values as strings
- Always convert with `Number()` before arithmetic operations
- Always cast types explicitly in JOINs with UUID columns: `project_id::UUID`

### Column Name Fixes
- Use `boq_item_id` not `boq_id` in boq_items table
- Use correct column names in ORDER BY (e.g., `name` not `cost_center_name`)

### apiResponse.success() Wrapper in Dashboard (2026-02-09)

**ProcurementDashboard RFQ fetch bug**: `/api/procurement/rfq` uses `apiResponse.success(res, { rfqs: [...] })` which wraps data in `{ success: true, data: { rfqs: [...] } }`. The dashboard was reading `rfqsData.rfqs` (undefined) instead of `rfqsData.data?.rfqs`.

**Fix pattern for wrapped APIs**: `const list = response.data?.rfqs || response.rfqs || []`

**Note**: BOQ API (`/api/procurement/boq`) uses `res.status(200).json()` directly (no wrapper). PO API uses `apiResponse.paginated()`. Inconsistent patterns across procurement APIs.
