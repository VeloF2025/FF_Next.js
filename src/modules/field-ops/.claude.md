# Field Ops Module

> **Last updated:** 2026-03-02
> **Status:** Active

## Overview

Field operations photo pipeline for civil and optical installation groups. Receives WhatsApp photos from field teams, classifies them with VLM, tracks per-pole installation progress, and sends real-time ACK messages back to WhatsApp groups.

## Key Files

### Services (`src/modules/field-ops/services/`)

| Service | Purpose |
|---------|---------|
| `poleInstallClassifier.ts` | VLM photo classification (9 installation steps) + text pole number extraction |
| `poleInstallAckService.ts` | Session management, progress tracking, ACK message builder + bridge send |
| `poleInstallCompletionService.ts` | Links completed sessions to `construction_qa_reviews` |
| `fieldOpsPhotoService.ts` | Photo storage and retrieval |
| `fieldOpsVlmService.ts` | Cross-reference VLM results against poles table |

### API Routes (`pages/api/field-ops/`)

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/field-ops/wa-message` | POST | Receives WhatsApp messages from bridge (auth: `x-bridge-secret`) |
| `/api/field-ops/process-photos` | POST | Batch photo processing (cron) |

### Pages (`pages/field-ops/`)

| Page | Purpose |
|------|---------|
| `/field-ops` | Field ops dashboard |
| `/field-ops/otdr` | OTDR results viewer |
| `/field-ops/reports` | Field ops reports |

## Database Tables

| Table | Migration | Purpose |
|-------|-----------|---------|
| `pole_install_sessions` | 229 | Per-pole photo session tracking with step counts |
| `field_ops_wa_messages` | — | Raw WhatsApp messages from civil/optical groups |
| `field_ops_wa_photos` | — | Photo records with `classified_step` and `pole_install_session_id` |

## Architecture

```
WhatsApp civil group → Bridge (inline photo download) → POST /api/field-ops/wa-message
    ├─ Store message + photo records
    ├─ Fire-and-forget: poleInstallAckService.processPoleInstallPhoto()
    │   ├─ VLM classify step (poleInstallClassifier.ts)
    │   ├─ Find/create pole_install_session
    │   ├─ Cross-ref pole against project SOW
    │   ├─ Update session step counts
    │   ├─ Build ACK message
    │   └─ Send ACK to WhatsApp group via bridge /send-message
    └─ Text messages: handlePoleTextMessage() for pole number declarations
```

## Classification Steps

9 installation step types classified by VLM:

| Step | Required | Description |
|------|----------|-------------|
| BEFORE | 3 | Marked ground showing where hole will be dug |
| DEPTH | 1 | Measuring tape in hole showing depth |
| STUMPING | 3 | Pole planted/erected, various angles |
| COMPACTION | 1 | Cement/soil backfill (corner poles) |
| HOUSEKEEPING | 3 | Clean site around completed installation |
| DURING | bonus | Digging/preparation |
| ENDPLATE | bonus | End plates visible |
| LEVEL | bonus | Spirit level on pole |
| SIGNATURE | bonus | Sign-off sheet |

Standard pole: 11 required photos. Corner pole: 14 (adds compaction).

## Critical Rules

- **Auth**: `wa-message.ts` uses `x-bridge-secret` header (NOT withAuth middleware)
- **Body size**: 50mb limit on wa-message endpoint (photos are base64)
- **Fire-and-forget**: ACK pipeline runs async — endpoint returns 200 immediately
- **Neon serverless**: Uses `neon()` tagged templates (NOT `@/lib/db` pool)
- **Session resolution**: Priority: exact pole match > sender's active session > group fallback (4hr window)
- **VLM**: Qwen3-VL-8B at `http://100.96.203.105:8100`, 30s timeout
