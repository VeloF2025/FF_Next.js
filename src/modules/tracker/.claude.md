# tracker module

## Purpose
PON-level and Master construction progress tracking per project. Displays zone/PON/OLT port milestone dates, QA flags, and sign-up / activation counts. Supports both read-only view and inline editing for select fields. Also syncs with SharePoint for external reporting.

## Key Files
| File | Role |
|------|------|
| `components/MasterTrackerPage.tsx` | Master tracker view — all zones/PONs for a project |
| `components/MasterTrackerTable.tsx` | Table with inline editing for master tracker rows |
| `components/PonTrackerPage.tsx` | PON-level tracker page |
| `components/PonTrackerTable.tsx` | PON tracker table — milestone date columns |
| `components/ColumnFilter.tsx` | Column visibility toggle for tracker tables |
| `components/TrackerSelectListAdmin.tsx` | Admin UI for managing tracker select list values |
| `types/` | Type definitions directory |
| `types.ts` | `PonRow` interface + `emptyRow()` factory |

## API Endpoints
| Route | Method | Purpose |
|-------|--------|---------|
| `/api/projects/[projectId]/tracker` | GET/POST/PUT | Master tracker rows CRUD |
| `/api/projects/[projectId]/pon-stages` | GET/PUT | PON milestone stage updates |
| `/api/projects/[projectId]/sp-tracker` | GET | SharePoint tracker sync status |
| `/api/sharepoint/sync-trackers` | POST | Trigger SharePoint tracker sync |

## PonRow Key Fields
- `zone_no`, `hld_pon`, `z_pon`, `olt_port` — zone/PON identifiers
- `scope_poles`, `poles_planted` — civil work progress
- `cwc_poles_date`, `cwc_stringing_date`, `cwc_qa` — CWC milestone dates + QA flag
- `optical_splicing_date`, `optical_submitted_date`, `optical_activated_date` — optical milestones
- `atp_qa` — ATP QA flag
- `sign_ups`, `homes_po`, `activated`, `available` — commercial metrics

## Critical Rules
- Tracker rows use `crypto.randomUUID()` for client-side IDs before server assignment — never re-use client IDs
- SharePoint sync is one-way export (FF → SP), not bidirectional
- CWC and optical dates are milestone checkpoints — once set, only super_admin should clear them
- `ColumnFilter` state is local (not persisted) — each page load resets to default visible columns
