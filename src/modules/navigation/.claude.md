# Module: navigation

## Purpose
Centralized navigation system with module registry, dynamic tab routing, and permission-based visibility.

## Key Files
| File | Purpose |
|------|---------|
| `config/registry.ts` | Central registry for module navigation configs |
| `config/modules/*.config.ts` | Individual module navigation definitions (activate, fleet, procurement, etc.) |
| `components/ModuleTabs.tsx` | Top-level module navigation tabs |
| `components/SubTabs.tsx` | Secondary tab navigation within modules |
| `hooks/useModuleTabs.ts` | Hook for accessing module config and active tab state |
| `types/navigation.types.ts` | Navigation type definitions (ModuleNavigationConfig, TabConfig) |
| `types/route.types.ts` | Route and path type definitions |

## Module Configs
Each module has a config file defining:
- `moduleId`: Unique identifier
- `basePath`: Base URL path
- `tabs`: Array of tab configurations with paths, labels, icons, permissions
- `defaultTab`: Default tab when navigating to base path

Registered modules:
- `activate.config.ts` - Activate module tabs
- `assets.config.ts` - Asset management tabs
- `fleet.config.ts` - Fleet management tabs
- `maintenance.config.ts` - Maintenance tabs
- `procurement.config.ts` - Procurement workflow tabs
- `projects.config.ts` - Project management tabs
- `staff.config.ts` - Staff management tabs

## API Endpoints
No direct API endpoints - navigation is client-side only.

## Registry Functions
| Function | Purpose |
|----------|---------|
| `registerModuleConfig(config)` | Register a module's navigation config |
| `getModuleConfig(moduleId)` | Get config by module ID |
| `getAllModuleConfigs()` | Get all registered modules |
| `getModuleConfigByPath(path)` | Find module by URL path |

## Usage Pattern
```typescript
import { useModuleTabs } from '@/modules/navigation/hooks';

const { moduleConfig, currentTab, isActive } = useModuleTabs('activate');
// moduleConfig: full navigation config
// currentTab: currently active tab
// isActive(tabId): check if tab is active
```

## Critical Rules
- All module configs must be registered in `config/index.ts`
- Tab paths should match Next.js page routes exactly
- Use `getModuleConfigByPath()` for route matching (handles trailing slashes, query params)
- Tabs can have permission requirements - filter in UI based on RBAC
- Default tab redirects handled by page components, not navigation module
