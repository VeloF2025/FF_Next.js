# Module: action-centre
<!-- Keep under 50 lines - reference, don't duplicate -->

## Purpose
Unified billing-reconciliation dashboard that classifies FT deduction rows (N1-N5 notes), tracks 1Map serial fixes, raises NOC tickets, and surfaces automation rule-engine runs.

## Critical Rules
- NEVER use conditional SQL fragments via the Neon shim — use explicit query branches in `ReconTab` / `ItemsTab` handlers
- ALWAYS call `classifyReconRow()` (pure function) before writing any dispute/fix bucket — it is the single source of truth per RFC 2026-04-17 §5
- NEVER expose raw FT billing data outside `/api/activate/action-centre/*` — these routes require `activate.action_centre` permission

## Key Files
| File | Purpose |
|------|---------|
| `classifyReconRow.ts` | Pure classifier: maps oesSerial/ftSerial/lastFix/oltRejected → Classification bucket |
| `OverviewTab.tsx` | Headline counts, per-note breakdown, anomalies, last rule-engine run |
| `ReconTab.tsx` | Row-level FT billing recon table with dispute actions |
| `AutomationTab.tsx` | Rule-engine trigger UI and run history |
| `DisputesTab.tsx` | Disputable rows: already_fixed_still_billed bucket |
| `ItemsTab.tsx` | Actionable deduction items management |
| `TicketsTab.tsx` | NOC ticket linkage for billing disputes |

## Database Tables
- `ft_weekly_billing` - FT billed serials per week (source of recon rows)
- `ft_billing_deductions` - Per-DR deduction records with note classification

## Dependencies
- **External:** FiberTime billing export (weekly CSV ingestion)
- **Internal:** `@/lib/db-pool`, 1Map serial-fix service, NOC ticket module, `classifyReconRow.ts`
