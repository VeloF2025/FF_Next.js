# System Module

## Purpose
System administration and infrastructure monitoring components for FibreFlow. Contains dashboards for monitoring server health, QField infrastructure, comprehensive system-wide health monitoring, and admin operations.

## Key Components

### Infrastructure Health Dashboard (`components/InfrastructureHealthDashboard.tsx`)
- **Purpose**: Comprehensive system-wide health monitoring
- **Features**:
  - Real-time monitoring of 14+ services across 6 categories
  - Auto-refresh every 30 seconds
  - Color-coded status cards (up/down/degraded/unknown)
  - Critical service indicators
  - Health trend chart (24-hour history)
  - Recovery actions log
- **Route**: `/system/infrastructure` (admin-only)
- **API**: `/api/system/health`

### Service Status Card (`components/ServiceStatusCard.tsx`)
- Reusable component for displaying individual service health
- Supports compact and expanded modes
- Shows latency, status, and error messages

### Health Trend Chart (`components/HealthTrendChart.tsx`)
- 24-hour health history visualization
- Current, average, min, max percentages
- Color-coded bar chart

### QField Dashboard (`qfield/QFieldDashboard.tsx`)
- **Purpose**: Monitor QFieldCloud infrastructure and server health
- **Features**:
  - Service health monitoring (qfieldSync, cloudflared)
  - Docker container status
  - Database connection status
  - MinIO storage health
  - Server control operations (restart services, clear caches)
- **Route**: `/system/qfield-monitor` (App Router)

## API Endpoints

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/api/system/health` | GET | Comprehensive system health check (14+ services) |
| `/api/system/health?history=true` | GET | Health history for trend charts |
| `/api/system/health?save=true` | GET | Check and save snapshot to DB |
| `/api/system/qfield/health` | GET | QField infrastructure health status |
| `/api/system/qfield/restart` | POST | Restart QField services |
| `/api/system/qfield/clear-cache` | POST | Clear sync caches |

## Auto-Recovery (Cron)

**Script**: `/home/velo/scripts/fibreflow-health-check-v2.sh`
**Schedule**: Every 5 minutes

Actions:
- Restart failed systemd services
- Start stopped Docker containers
- Log recovery actions to database
- Send WhatsApp alerts for critical failures

## Common Issues

### Server Controls Not Working
- Ensure user has admin permissions
- Check SSH connectivity to Velocity server
- Verify systemd service names are correct

### Health Check Timeouts
- Server may be under heavy load
- Check network connectivity to 100.96.203.105
- Verify QFieldCloud containers are running

### No Historical Data
- Data appears after health checks run with `?save=true`
- Cron script saves snapshots every 5 minutes
