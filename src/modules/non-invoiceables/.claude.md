# non-invoiceables module

## Purpose
Unified Action Centre for tracking items that cannot be billed until resolved. Aggregates issues from four sources — pre-provisions, offline devices, OLT mismatches, and billing deductions — into a single actionable dashboard under the Activate module.

## Key Files
| File | Role |
|------|------|
| `components/NonInvoiceablesPage.tsx` | Main page — wraps all tabs |
| `components/OverviewDashboard.tsx` | Summary tiles + category breakdown |
| `components/ItemsTable.tsx` | Filterable table of individual issues |
| `components/BillingCrossRefTab.tsx` | Cross-reference against billing deductions |
| `components/CreateTicketModal.tsx` | Create NOC ticket directly from an issue |
| `index.ts` | Module exports |
| `types.ts` | Core types: NonInvoiceableCategory, IssueSource, ActionStatus |

## API Endpoints
| Route | Method | Purpose |
|-------|--------|---------|
| `/api/activate/non-invoiceables/overview` | GET | Aggregated counts per category |
| `/api/activate/non-invoiceables/items` | GET | List items (filterable by category/status) |
| `/api/activate/non-invoiceables/billing-crossref` | GET | Billing deduction cross-reference |
| `/api/activate/pp-data-resolve` | POST | Mark PP item as resolved |

## Issue Categories
| Category | Source | Meaning |
|----------|--------|---------|
| `pre_provision` | `oes_pp_data` | ONT pre-registered, not yet activated in OES |
| `serial_mismatch` | `offline_devices` / `olt_mismatch` | Drop# / ONT serial doesn't match across systems |
| `offline` | `offline_devices` | Device not active or fiber break (note5) |
| `low_signal` | `offline_devices` | Signal below -26dB threshold (note1) |
| `degraded` | `offline_devices` | Signal degraded >2dB vs link budget (note3) — monitor only |
| `missing_dr` | `ft_billing` | No DR photo submission on field app (note2) |

## Action Status Flow
`open` → `ticketed` → `in_progress` → `resolved` / `false_positive`

## Critical Rules
- This module replaces the old separate PP/Serial/OLT tabs — do not re-add those as standalone tabs
- Items can spawn NOC tickets via `CreateTicketModal` — ticket creation links back to the source issue
- `false_positive` status means reviewed and confirmed not a real issue — never auto-close these
- Historic records must NOT be bulk-modified by AI ops (scope to new data only)
