# Pipeline Management Module

## Purpose
Track potential projects through approval stages (wayleave, municipal, traditional council) before they become planned projects.

## Status
✅ Phase 1-4 Complete - Full approval workflow, document management, alerts, and Smartsheet sync

## Key Types

### Project Types (`types/project.types.ts`)
- `PipelineProject` - Core project entity with status, location, client, financial estimates
- `PipelineStatus` - new | qualification | approvals_in_progress | approvals_complete | po_pending | ready_to_plan | planned | on_hold | cancelled | lost
- `ProjectType` - greenfield | brownfield | extension | upgrade
- `Priority` - low | medium | high | critical

### Approval Types (`types/approval.types.ts`)
- `PipelineProjectApproval` - Individual approval gate per project
- `ApprovalCategory` - wayleave | municipal | environmental | traditional | other
- `ApprovalStatus` - not_started | internal_review | submitted | under_review | approved | rejected | conditionally_approved | requires_amendment | resubmitted | expired | renewed | withdrawn
- `InternalApprovalStatus` - pending_pm | approved_pm | approved_ops | rejected (2-level internal approval)
- `PipelineApprovalDocument` - Document attached to approval with verification status

## Pipeline Status Flow
```
new → qualification → approvals_in_progress → approvals_complete → po_pending → ready_to_plan → planned
                                                                              ↓
                                                                     on_hold / cancelled / lost
```

## Approval Status Flow
```
not_started → internal_review → submitted → under_review → approved/rejected
                    ↓                            ↓
              conditionally_approved    requires_amendment → resubmitted
                                                               ↓
                                                         approved/rejected
```

## Internal Approval (2-level)
```
pending_pm → approved_pm → approved_ops → APPROVED (can submit externally)
    ↓             ↓              ↓
 rejected     rejected       rejected
```

## Key Features
1. **Approval Gates**: Visual progress through required approvals
2. **Expiry Tracking**: Automatic alerts at 90/30/7 days before expiry
3. **Internal Workflow**: 2-level approval (PM → Ops) before external submission
4. **Document Management**: Upload, verify, track documents per approval
5. **Follow-up Scheduling**: Track next follow-up dates with reminders
6. **Activity Logging**: Full audit trail of all actions
7. **Smartsheet Sync**: Bi-directional sync with Velocity_Master_Tracker

## Learnings

### UI Alignment (Feb 2026)
**Issue**: PipelineDashboard had manual stat cards and a `max-w-7xl mx-auto` wrapper, inconsistent with Activate/Fleet/Staff pages.

**Fix**:
- Replaced manual stat cards with `StatsGrid` from `@/components/dashboard/EnhancedStatCard` (colored top accent bar, `shadow-sm hover:shadow-md`, proper dark mode)
- Removed `max-w-7xl mx-auto` wrapper — all module pages flow full width within `ModulePage`'s `p-6`
- AlertsDashboard compact cards: dark mode opacity `900/20` → `900/30`, padding `p-3` → `p-4`, gap `gap-3` → `gap-4`
- Added `border border-[var(--ff-border-light)]` to "Requires Immediate Attention" section

**Rule**: Never add `max-w-7xl` inside module dashboards — `ModulePage` handles content width.

### Document Proxy Pattern (Jan 2026)
**Issue**: Direct storage URLs (`http://100.96.203.105:8091/...`) don't work from browser due to CORS/mixed content.

**Solution**: Created `/api/pipeline/documents/[...path]` proxy endpoint that:
- Routes requests through Next.js API
- Fetches from storage API server-side
- Sets proper content-type headers
- Enables inline PDF display
- Adds caching headers (24hr)

**Usage in components**:
```typescript
// Convert storage URL to proxy URL
function getDocumentViewUrl(fileUrl: string | null, filePath: string | null): string | null {
  if (filePath) {
    return `/api/pipeline/documents/${filePath}`;
  }
  // Parse fileUrl and extract path...
  return `/api/pipeline/documents/${extractedPath}`;
}
```

### FK Constraints Reference staff(id) — Dropped (Feb 2026)
**Issue**: All pipeline tables had `REFERENCES staff(id)` on user-related columns (`uploaded_by`, `pm_approved_by`, `created_by`, etc.), but the app passes `users` table UUIDs from auth context. This caused FK constraint violations on document upload, PM approve/reject, and any operation writing a user ID.

**Fix**: Dropped all 19 FK constraints across 5 pipeline tables:
- `pipeline_projects` (7 constraints)
- `pipeline_project_approvals` (5 constraints)
- `pipeline_approval_documents` (2 constraints — `uploaded_by` and `verified_by`)
- `pipeline_activity_log` (1 constraint)
- `pipeline_expiry_alerts` (1 constraint)
- `pipeline_service_authorities` (3 constraints)

**Rule**: Pipeline user ID columns are audit-only — no FK enforcement needed. The `users` and `staff` tables use different UUID spaces.

### Hard Delete (Feb 2026)
**Change**: `DELETE /api/pipeline/projects/[id]` now performs cascade hard delete instead of soft delete.
**Cascade order**: `projects` unlink → `project_pipeline_links` → `pipeline_approval_documents` → `pipeline_project_approvals` → `pipeline_projects`

### Layout Flash Prevention
**Issue**: Pages with conditional rendering (`{data && <Component />}`) cause layout shift when data loads.

**Solution**: Always render container, use skeleton placeholders:
```tsx
// ❌ Bad - causes flash
{waStats && <StatsCard data={waStats} />}

// ✅ Good - no flash
<div className="stats-card">
  {waStats ? <StatsContent data={waStats} /> : <SkeletonLoader />}
</div>
```
