# Module: Mission Control

## Purpose
Real-time monitoring dashboard for system agents, tasks, and infrastructure health. Provides visibility into agent status, live message feeds, task management, and system resource utilization.

## Key Files
| File | Purpose |
|------|---------|
| `MissionControlDashboard.tsx` | Main dashboard component with tab navigation (Dashboard, Live Feed, Agents, Task Board) |
| `types.ts` | TypeScript interfaces for agents, messages, tasks, and system health |
| `hooks/useMissionControl.ts` | Custom hook managing dashboard data, polling, and task operations |
| `components/DashboardTab.tsx` | Overview with stats, agent status cards, and system health |
| `components/LiveFeedTab.tsx` | Real-time message stream with agent communications (3s polling) |
| `components/AgentsTab.tsx` | Detailed agent cards with status, capabilities, and last activity |
| `components/TaskBoardTab.tsx` | Kanban board for task management (pending → in-progress → completed) |
| `components/SystemHealthPanel.tsx` | System metrics (memory, disk, load average, uptime) and service status |

## API Endpoints
| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/mission-control/dashboard` | Fetch all dashboard data (agents, stats, system health, services) |
| GET | `/api/mission-control/messages?limit=50` | Fetch recent agent messages (live feed) |
| POST | `/api/mission-control/tasks` | Create new task for agents |
| PATCH | `/api/mission-control/tasks/{id}` | Update task status or properties |
| DELETE | `/api/mission-control/tasks/{id}` | Delete task |

**Note:** All endpoints proxy to `http://127.0.0.1:3847/api` (Mission Control backend). Requires `super_admin` or `system` role.

## Data Structures

### MCAgent
```typescript
{
  agent: string;              // Agent name (e.g., "jarvis", "velo", "qfield")
  status: 'online' | 'offline' | 'busy';
  current_task: string | null;
  last_active: string;        // ISO timestamp
  last_heartbeat: string;     // ISO timestamp
  type: string;               // Agent type/category
  role: string;               // Agent role description
  capabilities: string;       // Comma-separated list
}
```

### MCTask
```typescript
{
  id: number;
  title: string;
  description: string | null;
  status: 'pending' | 'in-progress' | 'completed';
  assigned_to: string | null; // Agent name
  created_by: string | null;
  created_at: string;
  updated_at: string;
  completed_at: string | null;
  priority: 'low' | 'normal' | 'high' | 'urgent';
  tags: string | null;
}
```

### MCMessage
```typescript
{
  id: number;
  ts: string;                 // ISO timestamp
  from_agent: string;
  to_agent: string | null;    // null for broadcast
  message: string;
  type: string;               // 'heartbeat', 'command', 'response', 'error', 'info', 'task'
  metadata: string | null;
}
```

### MCSystemHealth
```typescript
{
  uptimeSeconds: number;
  memory: { total, available, used, percent };
  disk: { total, used, available, percent };
  loadAvg: number[];          // [1min, 5min, 15min]
}
```

## Polling Strategy
- **Dashboard data** (agents, stats, system health, services): 10 seconds
- **Live feed messages**: 3 seconds (only when on Live Feed tab to save bandwidth)
- **Auto-scroll**: Message feed auto-scrolls to bottom; user can disable with button

## Critical Rules
1. **Role-based access**: Only `super_admin` and `system` roles can access Mission Control (/api/mission-control endpoints)
2. **Backend proxy**: All API calls are proxied through `/api/mission-control/[...path].ts` to `http://127.0.0.1:3847/api` (must be running)
3. **Agent colors**: Pre-defined agent colors in constants (`jarvis: #3b82f6`, `velo: #22c55e`, `qfield: #a855f7`)
4. **Task deletion**: Requires user confirmation with native confirm() dialog
5. **Task state flow**: pending → in-progress → completed (with reverse navigation buttons)
6. **Time formatting**: Uses South Africa timezone (`'en-ZA'`) for consistency
7. **Error handling**: Silent failures for message polling; connection errors shown in banner on main dashboard
8. **Loading state**: Spinner shown on dashboard while loading; refetch button disabled during load

## Known Features
- **Agent health tracking**: Online/offline/busy status with last active timestamp
- **Task Kanban board**: Drag workflow with priority and assignment badges
- **System monitoring**: Real-time memory, disk, and load averages with color-coded health
- **Live message feed**: Agent-to-agent or broadcast communication with type badges
- **Service status**: Monitor external services (VLM, QField Sync, WA services) port availability

## Common Gotchas
- Mission Control backend must be running on `http://127.0.0.1:3847` or all API calls fail (503/502)
- Live feed only polls when the Live Feed tab is active (optimize for bandwidth)
- Timestamps are UTC strings; all formatting handles timezone conversion client-side
- Task operations trigger full dashboard refetch (not optimistic updates)
- Agent config hardcoded; new agents need entry in `AGENT_CONFIG` map for icons/colors

## Integration Points
- **Backend**: External Mission Control service on localhost:3847 (separate system)
- **Auth**: Uses project-standard `withAuth` middleware requiring session/role
- **Layout**: Uses `AppLayout` for consistent header/sidebar
- **Styling**: Uses CSS custom properties (`--ff-*`) for theming
