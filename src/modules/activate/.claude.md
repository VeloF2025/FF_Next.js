## Learnings (Consolidated 2026-01-21)

### OES-Only Records Filtering
- Records with `is_oes_only = TRUE` should NEVER appear in QA Centre
- They have no WhatsApp submission to review
- Use `(u.is_oes_only = FALSE OR u.is_oes_only IS NULL)` in queries
- Don't use COALESCE fallback on `submitted_date` for date filters

### SharePoint Sync
- Health check includes SharePoint: `/api/activate/health-check`
- Sync triggered on QA completion via `final-decision.ts`
- Credentials in `.env.production` (NOT tracked in git)
- Environment vars: `SHAREPOINT_TENANT_ID`, `SHAREPOINT_CLIENT_ID`, etc.

### Staging Port Conflict (2026-01-22)
- 500 errors on `/api/activate/drops` caused by port 3006 held by stale process
- Diagnosis: `sudo journalctl -u fibreflow.service -n 100` → EADDRINUSE
- Fix: `sudo fuser -k 3006/tcp && sudo systemctl restart fibreflow.service`

### qa_photo_reviews Auto-Sync (2026-01-23)
- DRs submitted via WhatsApp go to `qa_photo_reviews` first
- `process-new-dr.ts` webhook should create `dr_photo_unified_reviews` record
- If webhook fails, DRs are "invisible" in `/activate` (only queries unified table)
- Fix: `syncMissingFromQaPhotoReviews()` in `/api/activate/drops.ts`
- **Business rule**: Only sync DRs that ALSO exist in `oes_activations`
- DRs appear in /activate ONLY after OES import
