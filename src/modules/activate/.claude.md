## Learnings (Consolidated 2026-01-21)

### OES-Only Records Filtering
- Records with `is_oes_only = TRUE` should NEVER appear in QA Centre
- They have no WhatsApp submission to review
- Use `(u.is_oes_only = FALSE OR u.is_oes_only IS NULL)` in queries
- Don't use COALESCE fallback on `submitted_date` for date filters

### SharePoint Sync
- Health check includes SharePoint: `/api/activate/health-check`
- Sync triggered on QA completion via `final-decision.ts`
- Credentials in `.env.production` (NOT tracked in git)
- Environment vars: `SHAREPOINT_TENANT_ID`, `SHAREPOINT_CLIENT_ID`, etc.

### 4-Way Serial Verification System (2026-01-24)

1. **OES** - Original activation record (reference truth)

### Invalid DR Tracking & Data Reconciliation (2026-01-26)

**OES = Single Source of Truth** for activated links. DRs not in OES are NOT activated.

**DR Anomaly Categories:**
| Type | Count | Status | Action |
|------|-------|--------|--------|
| INVALID_FORMAT | 5 | `INVALID_DR` | Flagged - test data, typos with spaces/colons |
| TOO_SHORT | 3 | `INVALID_DR` | Flagged - truncated DR numbers |
| TOO_LONG | 1 | `INVALID_DR` | Flagged - extra digits |
| Valid, not in OES | 162 | Normal | **Pending activation** - submitted via WA but not yet activated |

**Reporting Invalid DRs:**
```sql
SELECT drop_number, created_at, photo_count
FROM dr_photo_unified_reviews
WHERE overall_status = 'INVALID_DR'
ORDER BY created_at DESC;
```

**Reporting Pending Activations (WA submitted, not in OES):**
```sql
SELECT r.drop_number, r.created_at, r.photo_count
FROM dr_photo_unified_reviews r
WHERE r.overall_status != 'INVALID_DR'
  AND NOT EXISTS (SELECT 1 FROM drops d WHERE d.drop_number = r.drop_number)
ORDER BY r.created_at DESC;
```
