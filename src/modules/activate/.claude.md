## Purpose
DR photo review with VLM AI categorization, 5-phase QA wizard, and WhatsApp integration.

## Critical Rules
- NEVER bypass VLM health check before categorization
- ALWAYS validate prerequisites before Phase 2 (photo review)
- ALWAYS use `qaAutoFailService.getTechnicianIssues()` for WA feedback (not internal QA issues)
- NEVER send VLM comparison results to technicians (internal only)
- VLM serial comparison in ACKs requires **>= 95% confidence** - below that, prompt "please double-check" instead
- Bridge ACK API (`dr-acknowledgment.ts`) uses bridge secret auth, NOT `withAuth`

### UNIFIED ARCHITECTURE (2026-01-26)

### Reporting API Response Pattern (2026-02-09)

**Three bug patterns found and fixed across all 10 reporting tabs:**

1. **apiResponse.success() wrapper mismatch**: Reporting APIs should use `res.status(200).json(response)` directly, NOT `apiResponse.success(res, response)`. The wrapper adds `{ success: true, data: {...} }` but frontends expect unwrapped data via `setData(await res.json())`.
   - Fixed in: `serial-swaps/index.ts`, `serial-mismatches/index.ts`

2. **Icon props as ReactNode**: `ReportCard` accepts `icon?: ReactNode`. Must pass JSX elements (`icon={<Repeat className="h-4 w-4" />}`) not component refs (`icon={Repeat}`). Component refs cause React error #31.
   - Fixed in: `SerialSwapReports.tsx`

3. **Incomplete optional chaining**: `data?.summary.x` only guards `data` being null, not `summary`. Must use `data?.summary?.x` and `(value ?? 0).toFixed(1)` for `.toFixed()` calls.
   - Fixed in: `TeamReports.tsx`, `FunnelReports.tsx`, `TrendReports.tsx`, `SerialSwapReports.tsx`

**Rule**: All reporting components should use full optional chaining: `data?.summary?.property` and `(data?.summary?.numericProp ?? 0).toFixed(N)`.

### DB Connection: Singleton Pool (2026-02-08)

**All reporting APIs must use `import pool from '@/lib/db'`** (pg TCP Pool singleton), NOT `@neondatabase/serverless` Pool (WebSocket). The serverless Pool silently fails in Node.js server environments, returning 500 errors.
- 9 of 11 reporting endpoints were broken by this
- Fixed by migrating to `pool.query()` or `const client = await pool.connect()`

### VLM Serial Confidence in ACK Messages (2026-02-12)

**Problem**: Blurry WA serial photos produced low-confidence VLM reads that showed false "MISMATCH" warnings, misleading techs to change correct serials in 1Map.

**Fix in `dr-acknowledgment.ts` → `buildSerialWarningLines()`:**
- **>= 95% confidence + match**: Show `✅` confirmation
- **>= 95% confidence + mismatch**: Show mismatch warning with correction prompt
- **< 95% or no VLM result**: Show serial + `📷 Please double-check ONT/UPS serial`

### ONT Swap Tracking (2026-02-12)

**Purpose**: Field teams swap ONTs on existing drops. New serial reported in WA pre-provision groups.

**Flow**: WA group message → bridge → `/api/activate/wa-swap-message` → `ont_swap_records` table → auto-confirmed when OES import picks up new serial.

**Key files**: `swapMessageParser.ts`, `wa-swap-message.ts`, migration `176_ont_swap_tracking.sql`

### Bridge ACK Architecture (2026-02-12)

**Flow**: VPS bridge → `POST vf.fibreflow.app/api/activate/dr-acknowledgment` → formatted message → bridge sends to WA group.

**Auth**: All bridge endpoints use `WA_BRIDGE_SECRET` env var, NOT `withAuth`. Endpoints: `dr-acknowledgment.ts`, `process-new-dr.ts`, `wa-swap-message.ts`, `inbound.ts`.

**Manual ACK recovery**: Use bridge `/api/send` endpoint (no dedup, no mentions) with `recipient` = group JID.
