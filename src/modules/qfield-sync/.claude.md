# Module: qfield-sync
<!-- Keep under 50 lines - reference, don't duplicate -->

## Purpose
QField mobile GIS app synchronization for field data collection.
Bidirectional sync between QFieldCloud (GIS) and FibreFlow database.

## Critical Rules
- ALWAYS validate GeoJSON format
- Handle offline sync conflicts
- Maintain data integrity
- Use `http://minio:9000` (internal DNS) for MinIO, NEVER `172.17.0.1:8009` (Docker bridge)
- CSRF patch is now **permanent** via entrypoint-wrapper.sh (no manual re-apply needed)
- After `.env` changes: restart BOTH `app` AND `worker_wrapper` (workers have own STORAGES copy)

## Learnings

### 2026-02-12: STORAGES endpoint_url must use internal DNS
**Problem:** HTTP-524 timeout. Django STORAGES used `172.17.0.1:8009` (Docker bridge) which was unreachable.
**Fix:** Changed to `http://minio:9000` in `.env` STORAGES JSON.

### 2026-02-12: CSRF patch made permanent via entrypoint wrapper
**Problem:** Manual `sed` CSRF patch lost on every `docker-compose up -d app` (recreate). The `sed '61a'` command also broke by joining lines, causing SyntaxError that crashed Django entirely.
**Fix:** Created persistent entrypoint-wrapper.sh that auto-applies CSRF patch on every container start:
- `/opt/qfieldcloud/entrypoint-wrapper.sh` - Wrapper script (mounted read-only)
- `/opt/qfieldcloud/settings_csrf_patch.py` - CSRF Python code (mounted read-only)
- `docker-compose.override.yml` - Mounts both + sets custom entrypoint

### 2026-02-12: Workers also need STORAGES endpoint update
**Problem:** After fixing app container's MinIO endpoint, workers still used `172.17.0.1:8009`. Jobs (process_projectfile, delta_apply, package) kept failing with Connect timeout. 300+ zombie jobs accumulated.
**Fix:** `docker-compose up -d worker_wrapper` to recreate all 8 workers. Then cleaned up stuck jobs and retriggered failed projects.
**Key:** App and workers have SEPARATE env copies. Both must be recreated after `.env` changes.
