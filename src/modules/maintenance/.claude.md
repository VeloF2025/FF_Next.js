# Module: maintenance
<!-- Keep under 50 lines - reference, don't duplicate -->

## Purpose
Maintenance ticket system with QContact integration, team assignment, escalation workflows, verification tracking, and photo attachments.

## Critical Rules
- NEVER bypass escalation rules for overdue tickets
- ALWAYS sync with QContact for external tickets
- Check QA readiness before closing tickets
- **Storage: Use VF Storage API (port 8091) via `vfStorageAdapter`**

## Key Files
| File | Purpose |
|------|---------|
| `services/attachmentService.ts` | Photo/file uploads to Velo server |
| `services/escalationService.ts` | Escalation logic |
| `services/ticketEnrichmentService.ts` | Ticket data enrichment |
| `components/Verification/PhotoUpload.tsx` | Photo upload UI component |
| `types/attachment.ts` | Attachment type definitions |

## API Endpoints
| Method | Endpoint | Purpose |
|--------|----------|---------|
| GET | `/api/maintenance/tickets` | List tickets |
| POST | `/api/maintenance/tickets` | Create ticket |
| PUT | `/api/maintenance/tickets/[id]` | Update ticket |
| POST | `/api/maintenance/attachments/upload` | Upload photo/file |
| POST | `/api/maintenance/qcontact/sync` | Sync with QContact |

## Database Tables
- `maintenance_tickets` - Main ticket table
- `maintenance_attachments` - File attachments (path stored, not Firebase)
- `ticket_notes` - Notes and comments
- `ticket_activities` - Activity log

## Storage (Updated Jan 2026)
- **Uses:** VF Storage API at `100.96.203.105:8091` via `vfStorageAdapter`
- `attachmentService.ts` uses `vfStorage.uploadFile()` and `vfStorage.deleteFile()`
