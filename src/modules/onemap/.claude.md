# Module: onemap
<!-- 1Map/OneMap geographic data: properties, poles, drops, serial sync, stage tracking -->

## Purpose
Integrates with the 1Map external GIS system to manage fiber network properties (poles, drops, joints) — importing data, syncing ONT/UPS serials from dr-photo-api, and mapping to SOW records.

## Database Tables
- `onemap_properties` — core property records (pole_number, DR number, linked serials)
- `onemap_poles` + `onemap_drops` + `onemap_joints` + `onemap_installations` — network elements
- `onemap_imports` — import history
- `onemap_sync_queue` — deferred sync tasks
- `normalized_onemap` — view/materialized table for normalized data
- `sow_poles` — SOW pole records for mapping
- `sow_onemap_mapping` — join table linking onemap poles to SOW poles
- `pon_stage_tracking` — stage/stringing tracking (scope_string = metres of stringing)
- `qa_photo_reviews` — do NOT confuse with `drops` table (different context)

## Critical Rules
- `sync-serials.ts` still imports `@neondatabase/serverless` — migrate to `pg.Pool` when touching
- Serial data: ONT barcode = `br_ont_barcode`, UPS serial = `br_ser` (Mini-UPS/Gizzu) from `dr-photo-api` at `http://100.96.203.105:8003`
- `pon_stage_tracking.scope_string` is metres of stringing, not a string label (confirmed 2026-05-11)
- Two separate drop tables exist: `drops` (SOW imports via `/api/sow/drops`) and `onemap_drops` (this module)
- 1Map serial edits use Etienne's creds with rollback tracking
