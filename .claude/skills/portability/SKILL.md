# /portability — AI Config Portability Skill

Reads the project's `CLAUDE.md` as canonical source and generates equivalent configs for every
supported AI coding tool. Keeps all tools in sync — one edit in `CLAUDE.md`, re-run `/portability`.

---

## Invocation Modes

| Command | What it does |
|---------|-------------|
| `/portability` | Interactive: prompts which tools, generates for cwd |
| `/portability all` | Generates all supported targets for cwd |
| `/portability agents` | AGENTS.md only (fastest, covers Codex + Devin + Copilot base) |
| `/portability cursor` | Cursor rules only (.mdc + legacy .cursorrules) |
| `/portability copilot` | GitHub Copilot instructions only |
| `/portability windsurf` | Windsurf + Cline + Amazon Q (bundled) |
| `/portability --workspaces` | Batch: sweep ~/Workspace/*/ and generate AGENTS.md in each |
| `/portability status` | Show which config files exist vs missing in cwd |

---

## Step 1 — Locate and load the source

1. Check for `CLAUDE.md` in cwd. If not found, walk up toward git root (`git rev-parse --show-toplevel`).
2. Also load any `.claude/rules/*.md` files (path-scoped rules).
3. **Strip HTML comments** before processing: `<!-- ... -->` blocks — these are Claude-only and will
   leak into other tools' prompts verbatim if not removed.
4. **Resolve `@imports`**: Replace any `@path/to/file.md` directives with the referenced file content
   (max 5 hops, relative to the file containing the directive).
5. Do NOT include content from `CLAUDE.local.md` — that is local-only and never emitted downstream.

---

## Step 2 — Section mapping

Parse the CLAUDE.md into logical sections. Most projects follow this structure:

| CLAUDE.md Section | Maps to |
|-------------------|---------|
| Project Overview | → AGENTS: `## Project Overview` |
| Essential Directory Structure | → AGENTS: `## Project Structure` |
| Database Configuration | → AGENTS: `## Setup Commands` (connection strings + env vars) |
| Starting the Server | → AGENTS: `## Setup Commands` |
| Key Commands | → AGENTS: `## Setup Commands` |
| Git Workflow | → AGENTS: `## Development Workflow` |
| Development Guidelines | → AGENTS: `## Code Style` |
| Critical Rules / Anti-patterns | → AGENTS: `## Code Style` (append as "Critical Rules" subsection) |
| Protocols (PAI, NLNH, DGTS, Zero Tolerance) | → AGENTS: `## Code Style` (append as "Quality Protocols") |
| Module Documentation | → AGENTS: `## Project Structure` (append as "Key Modules") |
| Deployment | → AGENTS: `## Development Workflow` (append as "Deployment" subsection) |
| GitHub Workflow | → AGENTS: `## Development Workflow` |

If sections are not clearly delimited by headings, output the full CLAUDE.md content verbatim after a
brief preamble explaining the tool context.

## Step 3 — Generate target files

### 3a. AGENTS.md (default target)

**Purpose**: Universal compatibility file — read by OpenAI Codex CLI, Devin, and partially by
GitHub Copilot when no `.github/copilot-instructions.md` exists.

**Rules:**
- Location: `AGENTS.md` at project root (same level as CLAUDE.md)
- No YAML frontmatter
- Use standard H2 headings: `Setup Commands`, `Code Style`, `Testing Guidelines`,
  `Project Structure`, `Development Workflow`
- Hard cap: **32 KB** (Codex stops reading at this point)
- If the source exceeds 32 KB after inline expansion, truncate module documentation first
  (it's the lowest-priority section for Codex), then deployment detail, keeping core rules intact
- Add a header comment explaining the file's purpose:

```markdown
<!-- This file is auto-generated by /portability from CLAUDE.md. Do not edit manually. -->
<!-- To regenerate: run /portability agents in Claude Code -->
<!-- Canonical source: CLAUDE.md -->
```

**Template structure:**

### 3b. Cursor rules (optional)

**Modern format** — `.cursor/rules/*.mdc` (one file per logical concern):

Create these files (create `.cursor/rules/` dir if needed):

**`.cursor/rules/project-overview.mdc`**:
```
---
description: Project overview, stack, and directory structure
alwaysApply: true
---
[Project Overview + Directory Structure sections from CLAUDE.md]
```

**`.cursor/rules/code-standards.mdc`**:
```
---
description: Coding standards, critical rules, and quality protocols
alwaysApply: true
---
[Development Guidelines + Critical Rules + Protocols sections]
```

**`.cursor/rules/api-routes.mdc`**:
```
---
description: API route conventions and response patterns
globs: src/pages/api/**/*.ts,pages/api/**/*.ts,src/app/api/**/*.ts
---
[API-specific guidelines from CLAUDE.md]
```

**`.cursor/rules/git-workflow.mdc`**:
```
---
description: Git workflow and deployment rules
alwaysApply: true
---
[Git Workflow + Deployment sections]
```

**CRITICAL Cursor frontmatter rules:**
- Frontmatter MUST start on line 1 — no leading blank line (Cursor will silently ignore the file)
- `alwaysApply: true` → injected every message
- `globs:` → file-pattern scoped (comma-separated, no spaces between patterns)
- `description:` only (no globs, no alwaysApply) → Agent Requested (Cursor picks it up contextually)

**Legacy format** — `.cursorrules` (single file, for completions mode + older Cursor versions):
- Concat all sections into one file
- No frontmatter
- Add same auto-gen comment at top

---

### 3c. GitHub Copilot (optional)

**Location**: `.github/copilot-instructions.md`

**Rules:**
- Create `.github/` directory if it doesn't exist
- No frontmatter (Copilot ignores any frontmatter)
- Recommended length: 2 pages / ~500 words — Copilot's effectiveness drops beyond this
- Focus on: stack, code standards, critical rules — omit deployment details (not relevant to Copilot)
- Template:

```markdown
<!-- Copilot instructions auto-generated from CLAUDE.md by /portability -->
<!-- Canonical source: CLAUDE.md — do not edit manually -->

# GitHub Copilot Instructions — [Project Name]

## Tech Stack
[from Project Overview: framework, auth, database, storage]

## Code Standards
[from Development Guidelines: key rules only, < 300 words]

## Critical Rules
[from Critical Rules section: the most important anti-patterns to avoid]

## API Conventions
[API Response Standards section]

## Quality Gates
- [Key commands: lint, type-check, test]
```

If you need scoped instructions (different rules per file type), also create:
- `.github/instructions/api.instructions.md` with `applyTo: 'pages/api/**/*.ts'` frontmatter
- `.github/instructions/components.instructions.md` with `applyTo: 'src/components/**/*.tsx'`

### 3d. Windsurf / Cline / Amazon Q (optional, bundled)

All three support a similar per-file rules model. Generate from the same source:

**Windsurf** — `.windsurf/rules/` directory:

Create one `.md` file per section. Frontmatter required. Example:

**`.windsurf/rules/core-standards.md`**:
```
---
trigger: always_on
description: Core coding standards for this project
---
[Code standards content]
```

**`.windsurf/rules/api-conventions.md`**:
```
---
trigger: glob
globs: pages/api/**/*.ts
description: API route conventions
---
[API guidelines content]
```

**CRITICAL Windsurf rules:**
- `trigger` field is **required** in every workspace rule file
- Valid values: `always_on`, `manual`, `model_decision`, `glob`
- If `trigger: glob`, the `globs:` field is also required
- Root `AGENTS.md` (if emitting one) and global `~/.codeium/windsurf/memories/global_rules.md`
  must NOT have frontmatter
- Per-file cap: **12 KB** per rule file, **6 KB** for global rules

**Cline** — `.clinerules/` directory (same content as Windsurf, different frontmatter):
```
---
paths:
  - pages/api/**/*.ts
---
```
Use a YAML array under `paths:` (not comma-separated like Cursor).

**Amazon Q** — `.amazonq/rules/` directory:
- No frontmatter
- Plain markdown content only
- Flat naming: `core-standards.md`, `api-conventions.md`

## Step 4 — Size enforcement

Before writing any file, check estimated size:
- AGENTS.md: warn if > 28 KB, hard-truncate at 32 KB (truncate modules section first)
- Windsurf per-rule: warn if > 10 KB, hard-truncate at 12 KB
- Copilot instructions: warn if > 400 words, suggest trimming

## Batch mode: /portability --workspaces

When `--workspaces` flag is passed:

1. Find all workspaces: `ls ~/Workspace/` (or ask user if path differs)
2. For each workspace directory:
   a. Check if `CLAUDE.md` exists at root
   b. If yes: generate `AGENTS.md` (default) or the specified targets
   c. If no: skip and report "No CLAUDE.md found — skipping [workspace]"
3. Report a summary table with all workspaces processed

**Safety**: Never overwrite an existing `AGENTS.md` without checking its header. If it was manually
edited (no `/portability` auto-gen comment), ask the user before overwriting.

## Common gotchas (encode into every generation)

1. **Aider** only recognises `.aider.conf.yml`, not `.yaml` — skip Aider for now, noted for future
2. **Cursor .mdc** frontmatter must be on line 1 with no preceding blank line
3. **Windsurf** workspace rules must have `trigger:` field — omitting it silently disables the rule
4. **Codex** stops reading AGENTS.md after 32 KB — order content: critical rules first, modules last
5. **Copilot** `applyTo:` uses comma-separated globs; Cline `paths:` uses YAML array — don't mix
6. **HTML comments** in CLAUDE.md are Claude-only — strip before emitting to any other tool
7. **`CLAUDE.local.md`** is local-only — never emit to downstream targets
8. **Copilot** also reads `AGENTS.md` and `CLAUDE.md` at repo root as fallbacks — having AGENTS.md
   gives basic Copilot compat even without `.github/copilot-instructions.md`

```markdown
<!-- This file is auto-generated by /portability from CLAUDE.md. Do not edit manually. -->
<!-- To regenerate: run /portability agents in Claude Code -->
<!-- Canonical source: CLAUDE.md -->

# AGENTS.md — FibreFlow Next.js

> AI coding assistant context. Works with OpenAI Codex CLI, Devin, and other tools.

## Project Overview

FibreFlow Next.js — fiber network project management application.
- Framework: Next.js 14+ with App Router
- Auth: PostgreSQL-based, role-based (RBAC)
- Database: Self-hosted Supabase Postgres (Velocity server, localhost:5437)
- Storage: VF Storage (self-hosted, served via app.fibreflow.app/storage/)

## Project Structure

src/
├── modules/    # 58 feature modules (activate, wa-monitor, qfield, vlm, fleet, procurement, ...)
├── components/ # Shared UI (AppLayout standard)
├── services/   # API services
└── lib/        # Utilities

Key modules: Activate (VLM QA), WA Monitor (WhatsApp bridge), QField Sync (field data),
Fleet (vehicle management), Procurement (BOQ/RFQ/PO workflow).

## Setup Commands

npm run dev          # PORT=3004 — development with HMR
npm run build        # Production build
npm run ci:quick     # Local CI lint gates (run before PRs)
npm run lint         # ESLint
npm run type-check   # TypeScript check
npm test             # Vitest

Database: Supabase Postgres on localhost:5437 (shared dev+prod). See .claude/credentials.local.md.

## Code Style

- TypeScript — 100% type coverage, no `any`
- Files < 300 lines, components < 200 lines
- No `console.log` — use `log` from `@/lib/logger`
- No empty catch blocks — always log and handle
- API responses: use `apiResponse.success/notFound/error` from `@/lib/apiResponse`
- Dynamic params: use `[projectId]` not `[id]` — be specific
- Nested dynamic API routes FAIL on Vercel — flatten them
- No conditional SQL fragments via the Neon serverless shim

### Critical Rules
- Wait for server confirmation before showing success toasts
- No `console.log` — Zero Tolerance violation
- CLAUDE.local.md is local-only, never commit it

### Quality Protocols (NLNH + DGTS + Zero Tolerance)
- No fake tests — real assertions only
- No mocked implementations pretending to be real
- Say "I don't know" when uncertain; use confidence levels

## Testing Guidelines

npm test                     # Vitest unit tests
npm run ci:quick             # Lint + type-check (mandatory before PRs)
npm run antihall             # Validate code references exist

## Development Workflow

### Git
- ALL changes go through Pull Requests — never commit directly to master
- Branch naming: feature/<name>, fix/<name>, refactor/<name>
- Run npm run ci:quick before creating any PR

### Deployment
- Dev: dev.fibreflow.app (port 3005, always allowed)
- Production: app.fibreflow.app (port 3000, after-hours only, needs approval)
- ALWAYS use: bash scripts/deploy-local.sh dev|production
- NEVER manual git pull + build + restart (causes 500s during build)
- Production deploys blocked 08:00–17:00 SAST (Mon–Fri)
```
