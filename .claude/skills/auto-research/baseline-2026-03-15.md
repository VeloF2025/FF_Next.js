## 3. SQL Performance

### Top 5 Heaviest Queries

| Rank | File | Complexity | Issue |
|------|------|-----------|-------|
| 1 | `trendAnalysisService.ts` | COMPLEX | 2 queries × 3 CTEs each with `generate_series` date spine + cross-joins. **No caching.** |
| 2 | `boq-lifecycle.ts` | COMPLEX | Main query: 4 aggregating LEFT JOIN subqueries each scanning PO/GRN/invoice tables independently |
| 3 | `teamPerformanceService.ts` | COMPLEX | 5 **sequential** pool queries (not parallelized) with `ARRAY_AGG(DISTINCT)` |
| 4 | `activate/drops.ts` | COMPLEX | `SELECT u.*` fetches ALL columns including JSONB blobs across 4 CTEs + 4 LEFT JOINs |
| 5 | `boq-spend-summary.ts` | MEDIUM-HIGH | 4 correlated subqueries per project row — scales O(N×4) |

### SELECT * Usage
- **100 files** use `SELECT *`
- Worst: `stock-items/index.ts` has **14 separate `SELECT *` queries**
- `activate/drops.ts` fetches JSONB blobs (`photos_metadata`, `vlm_categorization_results`, `submission_history`) on every page load

### Caching Gap
| Has Cache | Doesn't Have Cache |
|-----------|-------------------|
| Contractors, Projects, Clients, Teams, SOW, Documents, DR Lookup, RBAC permissions | **ALL reporting queries**, activate stats, procurement aggregates, BOQ lifecycle, team performance, trend analysis |

No Redis/external cache exists — everything is in-process `Map`/`LRUCache`.

## 4. VLM Prompts

### Prompt Inventory (16 prompts across 6 services)

| Prompt | Tokens | Few-Shot | HITL Metrics | Critical Weakness |
|--------|--------|----------|--------------|-------------------|
| Power meter | 110 | Yes | Yes | Range inconsistency (-5 to -35 vs -8 to -28 elsewhere); no negative sign reminder |
| ONT serial back | 273 | Yes | Yes | Statistical bias (64%/26%/10% hints may override visual read) |
| Step 9 front | 377 | Yes | Yes | Dual extraction (serial + DR) increases hallucination risk |
| Serial confirmation | 156 | No | Partial | 2-char tolerance = 25% of hex suffix — too generous |
| **Photo categorization** | **676+** | Yes | Yes | Batch index misalignment risk; Step 10/8 weak anchors |
| **QA validation** | 170-247 | **No** | **No** | Only production prompt WITHOUT learning loop; checks physical dimensions |
| Odometer | 260 | Yes | Yes | Multi-pass doubles cost; digit descriptions in prose unhelpful on blur |
| **License plate** | **78** | **No** | **No** | Critically thin — no SA format variants, no dirty/partial plate handling |
| **Fuel gauge** | 176 | **No** | **No** | Only 5 buckets; reversed gauge unhandled |
| **Fuel receipt** | 169 | **No** | **No** | No per-field confidence; SA date format DD/MM/YYYY not covered |
| **License disk** | 260 | **No** | **No** | Windscreen glare; VIN 17-char not enforced |
| Construction QA | 286 | Yes | Partial | Only Civil discipline well-covered |
| **Field ops civil** | **59** | **No** | **No** | Critically compressed — entire checklist in 2 sentences |
| **Field ops optical** | **59** | **No** | **No** | Same — no JSON schema hints |
| **Asset label** | 143 | **No** | Partial | No negative examples; no field confusion guards |
| **Unified VLM** | 78 | **No** | **No** | **BUG: Math.random() scores on API failure**; deprecated step numbering |

### Critical Bug
`unifiedVlmService.ts` line 186-194: On VLM API failure, returns `Math.random()` scores with `passed: Math.random() > 0.3`. If this code path is reachable, it silently produces fabricated QA results.

### HITL Coverage Gap
7 of 16 prompts have NO few-shot injection despite the infrastructure existing. 8 of 16 have NO metrics recording.
